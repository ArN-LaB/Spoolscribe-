# Validation de préparation — SpoolScribe v0.4.0 / OpenTag3D

**État : développement, aucune release v0.4.0 publiée.** Branche
`feature/v0.4.0-opentag3d`. La stable v0.3.5, son tag et ses six fichiers restent inchangés.

L’intégration du code dans `main` est autorisée par l’utilisateur, sous réserve
des contrôles Git et CI. Cette autorisation ne vaut pas publication d’une release.
La campagne locale consignée ci-dessous reste distincte des contrôles CI de la PR.

Une nouvelle exécution avant commit confirme **318/318** tests sur Python 3.10.20
(25,256 s) et **318/318** sur Python 3.12.13 (22,496 s), sans exception Qt dans les
logs. Le contrôle du dépôt, `git diff --check` et les 54 empreintes protégées passent.
Le formulaire de compatibilité accepte les essais réussis et les anomalies, sans
réclamer de données personnelles. Les binaires publics v0.3.5 ne sont pas remplacés
par cette intégration du code source.

### Intégration GitHub autorisée

La [PR #12](https://github.com/ArN-LaB/Spoolscribe-/pull/12) porte les commits
signés et les contrôles distants. Le [premier build manuel](https://github.com/ArN-LaB/Spoolscribe-/actions/runs/41321216362)
a exécuté les quatre suites : Linux 3.10/3.12 et macOS 3.12 réussis ; Windows 3.12
échoué dans le test d’export CLI. Les builds ont donc été ignorés, pas réussis.

Cause : le CLI écrit déjà en UTF-8, mais le nouveau test utilisait l’encodage
implicite Windows-1252 de `subprocess.run`, provoquant `UnicodeDecodeError` dans
la lecture de sa sortie. Le défaut a été reproduit localement en imposant cet
encodage implicite. La capture précise désormais `encoding='utf-8'` ; les deux
tests CLI passent sous cette même simulation. Aucun test, support de plateforme
ou contrôle n’est supprimé, et aucun encodage métier n’est modifié.

Les nouveaux résultats CI sont consultables dans la PR. Cette section conserve
l’échec initial au lieu de le présenter comme réussi. Les contrôles distants
ne constituent pas une recette matérielle des configurations d’imprimantes.

### Échec externe observé

Le premier essai de relecture mobile par le site officiel échoue : sa conversion
Latin-1/UTF-8 altère les octets supérieurs à 127. Le défaut se reproduit sur
**100/100 fichiers produits par son propre générateur** à cette révision.
Les sorties de SpoolScribe restent identiques au générateur officiel et conservent
les octets bruts. Aucun changement n’a été fait pour satisfaire ce lecteur défectueux.
La relecture base64 indépendante des profils est testée dans la suite locale.
Cet échec n’est pas présenté comme une recette d’import mobile réussie.

- Les API et sérialiseurs OpenSpool existants restent disponibles ; les 1 008
  exports historiques conservent leur empreinte de référence.
- Les 54 fixtures protégées, dont les 48 profils Orca, gardent leurs SHA-256.

### Vérifications ajoutées

Dix-huit nouveaux tests couvrent modes U1, prérequis USB, effet inventaire, accessoire
CAN, métadonnées, migrations des réglages, filtres de recherche et liens ouverts
uniquement au clic. La migration est contrôlée au démarrage et à l’import ;
un choix inconnu ou supprimé reste à confirmer après redémarrage, et une liste
actualisée recharge les installations sans confirmer une sélection inconnue. Aucun ancien test n’a été désactivé. Les assertions portant
sur l’ancienne entrée Prusa globale et sur Bambu sans choix d’installation ont été
adaptées aux modèles et choix désormais explicites.

Une première suite de 309 tests a affiché une erreur de slot Qt malgré son résultat
unittest `OK` : une sélection temporairement vide accédait à un profil `None`.
Cette anomalie a été reproduite dans un test dédié, puis corrigée ; un état vide
n’autorise plus l’export. Les logs finaux ne contiennent plus cette exception.
Le débordement horizontal de 51/85 pixels en petite fenêtre français/espagnol a
également été reproduit puis corrigé en séparant le tag des deux actions de réglage.

24 captures Qt offscreen (six installations, quatre langues) et un contrôle de
redimensionnement à 510 × 360 sans défilement horizontal ont été exécutés.
Le français U1/USB et le chinois Prusa inventaire ont été examinés visuellement.
Les probes dans le binaire contrôlent désormais également cinq installations
précises, y compris une configuration sans format exportable.

La couverture matérielle n’est pas exhaustive : disposer de toutes les imprimantes,
lecteurs et versions de logiciels serait nécessaire pour tester chaque combinaison.
Les tests logiciels et les sources documentaires ne sont pas présentés comme une
certification matérielle. Les essais réussis et les problèmes peuvent être signalés
via le [formulaire de compatibilité](https://github.com/ArN-LaB/Spoolscribe-/issues/new?template=printer_compatibility.yml)
pour préciser les configurations et corriger les anomalies.

- À la clôture de la campagne locale, tests et builds natifs Linux/Windows ainsi
  que GitHub Actions v0.4.0 non exécutés ; les exécutions d’intégration ultérieures
  sont suivies dans la PR #12. La campagne locale macOS ne les remplace pas.
- Import dans les applications NFC Tools installées, écriture et relecture sur
  de vrais NTAG215/216 : non exécutés.
- Lecture U1/OpenRFID et autres imprimantes : non exécutée. Vérifier le logiciel
  installé, le système de détection, le positionnement et l’absence de tag concurrent.
- Compatibilité d’import de fichiers SpoolFlux : non établie ; ne pas importer
  un profil NFC Tools comme s’il s’agissait d’un JSON OpenSpool.
- Encodeur OpenPrintTag : non implémenté. Les champs optionnels non proposés
  par cette première intégration restent non renseignés.
- Aucun firmware, service personnel, catalogue réel ou application installée modifié.

## Parcours par boutons demandé lors du retour utilisateur

Les sélecteurs techniques de configuration et de format sont désormais masqués.
Les boutons se combinent : type de lecteur, logiciel d’origine/modifié/ajouté,
installation précise, format et application d’écriture. Aucun simple choix USB
ou réseau ne confirme automatiquement un plugin, même si une seule installation
est documentée. Les anciens identifiants restent utilisés pour les réglages et la CLI.

Le résumé reste fixé sous la zone défilante. Les paramètres NFC avancés, le NDEF
brut, les noms de pilotes et les prérequis sont regroupés dans les détails repliés.
Les descriptions d’imprimante sont raccourcies, les visuels compacts et les actions
homogènes. Les contrôles sont traduits dans les quatre langues.

Trois parcours supplémentaires vérifient les clics réels de composition, la
confirmation obligatoire et la distinction inventaire/imprimante. La probe du
binaire reproduit aussi le parcours de boutons U1 dans chaque langue. Les listes
historiques ne servent plus d’interface visible mais restent testées comme état interne.
