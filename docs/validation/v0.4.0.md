# Validation — SpoolScribe v0.4.0 pre-release

Historical [v0.4.0 pre-release](https://github.com/ArN-LaB/Spoolscribe-/releases/tag/v0.4.0)
record. The user authorised pre-release publication on 1 November 2026. At that
stage v0.3.5, its tag and six files remained unchanged, and v0.4.0 could not replace
the stable Latest target. Earlier failures/limits remain recorded below.

Validated application code entered main through PR #12 as
`1156d27f5cc0c8a32d3b60cb3678c282aa4867be`. Release preparation updated documents,
Wiki and channel without changing catalogues/business formats. Public state,
tag and six files were accessible on the pre-release page.

A further pre-commit run passed **318/318** on Python 3.10.20 (25.256 s) and
**318/318** on Python 3.12.13 (22.496 s), with no Qt exceptions. Repository check,
diff-check and 54 protected hashes passed. Compatibility forms accepted successes
and problems without personal information. This source integration replaced no
v0.3.5 public binary.

## Authorised GitHub integration

[PR #12](https://github.com/ArN-LaB/Spoolscribe-/pull/12) carried signed commits and
remote checks. The [first manual build run](https://github.com/ArN-LaB/Spoolscribe-/actions/runs/41321216362)
passed Linux 3.10/3.12 and macOS 3.12, but Windows failed a CLI export test.
Builds therefore skipped, rather than passed.

The CLI already wrote UTF-8; the test's `subprocess.run` implicitly decoded as
Windows-1252, raising `UnicodeDecodeError`. This was reproduced locally by forcing
that encoding. Explicit `encoding='utf-8'` fixed capture; both CLI tests passed
under the same simulation. No test, platform support or check was removed and
business encoding did not change.

The [validated complete run](https://github.com/ArN-LaB/Spoolscribe-/actions/runs/41321578995)
passed four 318/318 suites and three builds, with frozen TLS/catalogue/OpenTag3D
probes on each system. Six downloaded files passed digest/CRC checks.
[Required push checks](https://github.com/ArN-LaB/Spoolscribe-/actions/runs/41321577143/attempts/2)
and [post-merge main checks](https://github.com/ArN-LaB/Spoolscribe-/actions/runs/41322719433)
also passed. Their skipped stages were not counted as builds; only the three
actual complete-run builds were. Initial Windows failure remains a failure,
not a retroactive success; remote software checks did not certify printer hardware.

## Scope

Independent OpenTag3D 2.004 encoder; reader/software-specific selection; NFC Tools

filament catalogue changes. OpenPrintTag and physical writing were excluded.

### Observed external failure

Initial official-site mobile rereading failed: Latin-1/UTF-8 conversion corrupted
bytes above 127. The same defect reproduced on **100/100 files from that site's
own generator** at this revision. SpoolScribe output remained identical to the
official generator and retained raw bytes; no change was made to satisfy the
broken reader. Independent profile base64 rereading was in the local suite.
This external failure was not presented as successful mobile import acceptance.

## Protections and compatibility

Existing OpenSpool APIs/serialisers and all 1,008 historical exports retained
reference digests. All 54 protected fixtures/48 Orca profiles retained SHA-256.
Legacy reader lists without `formats` kept OpenSpool behaviour; new OpenRFID was
distinct from historical paxx12. Bambu AMS, Prusa OpenPrintTag and stock U1 gained
no supported format. Settings import validated fields before save and explicitly
included reader software. No dependency, new domain or runtime network access was added.

## Reader-configuration clarification campaign

After the user's first local trial, the list described **20 visible choices,
39 setups, 18 export-capable setups**. Two old entries remained preference-only
aliases, without selector duplicates. Connection (built-in/USB/network/CAN/other)
and software (stock/modified/additional integration) were separated from data format.

OpenRFID/Generic were modes of the same paxx12, both offering OpenSpool/OpenTag3D;
Snapmaker mode remained OpenSpool-only. FF_NFC on Zmod, Kiln OS/AD5X and LaneTag
were distinguished, including USB requirements and Kiln OS's early status.
SpoolSense network entries covered U1/Klipper/Bambu and Prusa/Creality inventory
with actual effects; no universal USB support was inferred from USB power/ports.

The Prusa CORE One/L accessory was explicitly selected, never presumed: CAN,
firmware 8.0+, separate from MK4/MMU3 and an unspecified generic model. No
OpenPrintTag encoder was added. nfc2klipper documented old v0.12 OpenTag3D and
PN532 UART, not established 2.004 reading; that path enabled no export.
Insufficiently verified stock configurations stayed labelled/export-blocked;
the list was not exhaustive.

### Added checks and reproduced failures

Eighteen tests covered U1 modes, USB requirements, inventory effects, CAN
accessory, metadata, preference migrations, search filters and click-only links.
Migrations were checked on startup/import. Unknown/removed choices still needed
confirmation after restart; refreshing the list never confirmed an unknown
selection. No old test was disabled. Assertions for the former generic Prusa and
unspecified Bambu entry were adapted to explicit models/setups.

An early 309-test suite printed a Qt slot exception despite unittest `OK`: an
empty selection accessed a `None` profile. A dedicated reproducer then passed
after correction; empty state no longer allowed export, and final logs had no
exception. A **51/85-pixel** horizontal overflow in small French/Spanish windows
was reproduced and corrected by separating tag selection from settings actions.

Twenty-four offscreen captures (six setups/four languages) and a **510 × 360**
resize check ran without horizontal scrolling. French U1/USB and Chinese Prusa
inventory were visually reviewed. Frozen probes also checked five specific
setups, including one without any exportable format.

### Independent SpoolSense decoder

The C library from `SpoolSense/spoolsense_scanner`, revision
`6070713488b45e51d2dc81124882775253dee2f0`, was separately downloaded and compiled
with clang. All **100/100** deterministic SpoolScribe payloads recovered matching
version, material, manufacturer, diameter, mass, density, temperatures and four
RGBA values. All **100** emitted a minor-version warning: reader 2.003 versus
export 2.004. No third-party code was bundled, nor physical success or complete
tag rewriting inferred. [Setup documentation](../PRINTER-CONFIGURATIONS.md)
retained primary sources/limits. Local Wiki sources were updated, but the public
Wiki was not pushed during that development stage.

## Unexecuted checks and remaining risks

Exhaustive hardware coverage would require every printer/reader/software version.
Documentation/software results were not hardware certification.
[Compatibility reports](https://github.com/ArN-LaB/Spoolscribe-/issues/new?template=printer_compatibility.yml)
welcomed both successes and problems to clarify setups and correct defects.

At local-campaign closure, native Linux/Windows tests/builds and remote v0.4.0
Actions had not run; later integration runs are recorded in PR #12. Local macOS
results did not replace them. NFC Tools import in installed applications,
physical NTAG215/216 writing/read-back and U1/OpenRFID/other-printer reading were
unexecuted. Installed software, detection mode, positioning and absence of a
competing tag still needed checking.

SpoolFlux file import compatibility was not established. NFC Tools profiles must
not be treated as OpenSpool JSON. OpenPrintTag was unimplemented, and optional
fields outside this first integration remained unset. No firmware, personal
service, real catalogue or installed app was changed.
