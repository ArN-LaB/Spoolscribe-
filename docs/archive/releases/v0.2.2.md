## What changes for you

Resource bytes are checked against Git before packaging. OpenSpool validation preserves unknown values and refuses invalid/non-finite physical values or reversed ranges instead of inventing plausible-looking data.

against the accompanying checksum file. No Python installation is required for

The following details describe this version at its original publication stage,
including then-current stable-version statements. They do not redefine today’s latest release.

##### Fixed
- Use the validated PySide6/Shiboken 6.11.3 build set and exclude 6.12 to avoid
  the native `none_dealloc` crash observed on Linux with Python 3.10 (CI-01).
- Preserve bundled catalogue, profiles and worker bytes across OS checkouts;
  verify embedded resources against Git before packaging.
- Disable generated Python bytecode during builds to keep worker resources clean.
- Validate OpenSpool data before preview/export: no invented black color or
  manufacturer, no null/non-finite physical values or reversed ranges.
- Compact NFC JSON keeps the complete existing field set. Capacity checks use
  UTF-8 bytes plus one `application/json` NDEF record and Type 2 TLV framing.
  Readable archive exports remain available under a separate filename.
- GUI and CLI can explicitly supply a representative HEX and optional alpha
  for an unknown color. No transparency or multicolor values are inferred.
- Confine exported filenames to the output directory.
- Atomically save validated databases, preserve the last good revision and
  a separate pre-update backup, and report corruption or stale saves.
- Preserve local physical values at export unless the user explicitly selects
  the Orca override setting/CLI flag.
- Preserve local HEX and physical corrections during ordinary updates; merge
  additions from newer bundled catalogues without replacing existing values.
- Report unavailable sources and partial updates honestly. Only a fully
  successful pipeline advances the complete-refresh date.
- Allow the CLI to reconsider saved network consent; GUI settings can revoke it.

##### Tests and packaging
- Add offline catalogue, OpenSpool, NFC size, storage, updater, Orca and GUI tests.
- Run tests on pushes/PRs and require them before the existing three-OS builds.
- Record a Python 3.12 build dependency snapshot in `requirements-build.txt`.
- Include the shared storage helper in packaged worker execution.

##### Compatibility
- OpenSpool protocol/version stay `openspool` / `1.0`; metadata fields are retained.
- 74 missing HEX values and two orphan catalogue references remain explicit
  data-quality exceptions; no unverified catalogue correction is fabricated.
- No Spoolman integration or UID migration, firmware/NAS change or direct NFC writing.
- Hardware read-back and full interactive Windows/Linux acceptance require separate validation.

##### Archive correction — 2026-10-31

The macOS ZIP now contains only `SpoolScribe.app`. That archive-only correction preserved all executable bytes. The subsequent TLS packaging correction below supersedes those archives.

The packaging workflow now checks archive layout, native format and permissions. [Validation: 78 tests on four configurations and three successful builds](https://github.com/ArN-LaB/Spoolscribe-/actions/runs/41180046112).

##### TLS packaging correction — 2026-10-31

All three ZIPs and their SHA-256 files have been rebuilt and replaced to include
the certifi 2026.10.23 root certificate bundle and its license. The PyInstaller
runtime hook supplies this bundle only when Python finds no default trust roots.
Existing system roots and explicit SSL_CERT_FILE / SSL_CERT_DIR settings remain
authoritative. Certificate and hostname verification stay enabled.

The application business code, update workers, catalogue and all 48 Orca profiles
are unchanged. The signed v0.2.2 tag is unchanged; the packaging correction is
commit 3c80d8299762a80078f96154396b45c75b9a3181 on main. PySide6/Shiboken remain
6.11.3 and PyInstaller remains 6.22.3. The macOS ZIP still contains only the .app.

[Validation: 83 offline tests on four configurations, three successful builds,
and an offline TLS smoke test executed inside each native binary](https://github.com/ArN-LaB/Spoolscribe-/actions/runs/41181883286).
All 1,008 compatible OpenSpool exports and the 74 original embedded resources
were rechecked. The downloaded macOS binary also passed separate read-only HTTPS
checks against Wholesale, the Polymaker wiki, SpoolmanDB and the Orca index;
an invalid self-signed certificate was rejected. No real catalogue update or
physical NFC test was performed by these checks.

The bundled TheFilamentDB snapshot has no ROSA3D entries. Its corresponding
partial-source warning is independent of TLS and remains accurately reported;
this correction does not claim a fully successful 13/13 remote update.
