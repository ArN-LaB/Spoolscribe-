What Companion is

SpoolScribe Companion is the iPhone companion of SpoolScribe Desktop. Desktop prepares the NFC label of a filament spool and shows it as an SSQR1 QR code. Companion scans that QR, checks it, writes the same NFC message to a tag and reads it back.

Companion is not a catalogue: it shows only what the QR contains. Filaments are chosen and edited in SpoolScribe Desktop.

SpoolScribe Desktop — latest release Companion availability

Desktop and Companion have separate version numbers. To find the version and build of the Companion beta installed on your iPhone, open SpoolScribe Companion in the TestFlight app.

From Desktop to the tag

On an iPhone with a camera and NFC tag writing:

  1. Show the QR in SpoolScribe Desktop. Select a filament, then the “Show QR Code — SpoolScribe Companion” command.
  2. Scan it with Companion. The camera starts only when you tap the scan button. iOS asks for camera access the first time.
  3. Check the transfer. Companion decodes the QR, verifies its length and SHA-256 digest and the OpenSpool 1.0 or OpenTag3D 2.004 format, then shows the label. All of this happens offline on the phone.
  4. Write the tag, then read it back. After your confirmation, Companion writes the NDEF message to one tag and reads it back to compare it with the expected bytes. It never locks, formats or erases a tag.

Inspecting a tag is a separate, read-only action: Companion reads the NFC message of a tag you choose and explains what it contains. It writes nothing. A technical profile reading can also report the tag type, its capacity and a partially masked identifier (see the privacy policy).

A generic QR scanner can show the transfer text, but it does not program a tag and does not necessarily open Companion.

Simulation and demonstration

On a device without a camera or NFC tag writing, such as the iOS Simulator, Companion still decodes and checks transfers, but the write is simulated. Every simulated result is labelled “SIMULATION — no chip programmed”.

Development builds also offer demonstration texts and simulated outcomes (success, no tag, read-only tag, insufficient capacity, interrupted write, read-back mismatch). These are not measurements of a real phone or tag. Demonstration texts always stay simulated, even on an iPhone.

Phones, tags and printers

Companion requires iOS 15 or later. Scanning needs a camera; writing and inspecting need an iPhone that supports NFC tag reading and writing. Testing so far is internal: no phone model, tag type or capacity is certified, and no general hardware validation is claimed. Tag types named in the OpenSpool and OpenTag3D documentation, such as NTAG215/216, are examples from those formats, not guarantees for Companion.

Printer hardware is optional. In Preferences you can choose your printer and its configuration from a catalogue built into the app, which works offline. Companion then shows the conditions documented for that configuration (firmware, accessory, scope) and compares them with the formats of a tag you inspect. These are documentary indications from public sources, not a compatibility guarantee: recognising a format does not prove that a given printer, firmware or reader will use the tag.

Frequently asked questions

What is an SSQR1 QR, and why can’t a regular scanner program my tag?

SSQR1 is the SpoolScribe transfer format: the text SSQR1: followed by Base45 data containing the complete NFC message (OpenSpool 1.0 or OpenTag3D 2.004), its length and a SHA-256 digest — no server and no link. A generic QR scanner only displays that text. Writing a tag needs an app that decodes and validates the message and then uses the phone’s NFC, which is Companion’s role. Details: SSQR1 contract.

The camera does not start. What can I do?

Companion uses the camera only while you scan. If camera access was refused, allow it again in the iOS Settings app, under SpoolScribe Companion. On a device without a camera, scanning is not offered.

What does the SHA-256 check do, and why is my QR refused?

Companion recomputes the SHA-256 digest of the decoded NFC message and compares it with the one in the QR. A damaged or edited text, a wrong prefix, invalid characters, a text that is too long, or content that is not valid OpenSpool 1.0 or OpenTag3D 2.004 is refused, and no label data from it is shown. Display the QR again in SpoolScribe Desktop. SHA-256 detects changes; it does not prove who created the QR and does not encrypt it.

Why is a field missing, or different between OpenSpool and OpenTag3D?

The two formats carry different fields. Companion shows the values received in the QR, as they are: it does not merge them with another source, rebuild a missing name or fill an empty field. A missing value is shown as not provided.

OpenTag3D also defines two optional measurements: the measured tolerance of the filament diameter, and the minimum nozzle diameter advised for the filament (not the nozzle installed on your printer). Neither is needed to write a label. They can be useful when a reliable source provides them; Companion shows them as received and never estimates them. SpoolScribe Desktop v0.8.1 did not offer them as editable settings.

The write failed or the read-back does not match. What now?

Hold the tag still against the top of the iPhone until the end of the session, and use a tag with enough free capacity that is not locked. A read-back mismatch means the tag does not contain the expected message: write it again or use another tag. Companion never reports a write as successful without a matching read-back.

What does Companion remember?

Only your preferences: language, appearance and the optional printer hardware, kept on the iPhone. Transfers, previews, inspections (including a partially masked tag identifier) and write results stay in memory for the current session. See the privacy policy.

Report a problem

Preferred channel: e-mail SpoolScribe Support at spoolscribe@arnlab.simplelogin.com. Start the subject with Companion — .

Email SpoolScribe Support

Optional, for a public problem that contains nothing sensitive: open an issue on the SpoolScribe GitHub repository. Its forms are shared with SpoolScribe Desktop: start the title with Companion — and describe the mobile app in the body. A GitHub account is needed to open an issue; existing issues can be read without one.

Open a GitHub issue Read existing issues

Please include:

  • the Companion version and build, shown in the TestFlight app;
  • the iOS version and the iPhone model, or the simulator;
  • the protocol: OpenSpool 1.0 or OpenTag3D 2.004;
  • for a write or an inspection: the tag type and its announced capacity;
  • the steps, what you expected and what happened.

Issues are public. Use a synthetic example. Never post a confidential QR, a personal catalogue, credentials or personal data in an issue; if a report needs private details, send it by e-mail instead.

This is a hobby project: there is no guaranteed response time.

Security vulnerabilities: report them privately through GitHub vulnerability reporting, not in a public issue.
