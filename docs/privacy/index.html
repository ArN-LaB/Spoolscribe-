Who we are and what this covers

SpoolScribe Companion (“Companion”) is a mobile companion to SpoolScribe Desktop, an open-source filament label tool published under the public project name ArN-LaB on GitHub.

ArN-LaB is the public name of the project. Its developer and publisher is established in France. General contact: ArN-LaB Support, support@arnlab.simplelogin.com. Technical help: SpoolScribe Support, spoolscribe@arnlab.simplelogin.com. Privacy questions: ArN-LaB Privacy, privacy@arnlab.simplelogin.com (see Contacting the project).

This policy covers the Companion app. A separate section covers this website. SpoolScribe Desktop uses the network and stores files differently and has its own privacy policy, which does not cover Companion.

Companion is not a filament catalogue: it only shows what is contained in a transfer created by SpoolScribe Desktop.

What the app processes

Companion reads an SSQR1 transfer text — shown as a QR code by SpoolScribe Desktop — decodes it, checks it (length, bounded decompression, SHA-256 integrity, OpenSpool 1.0 or OpenTag3D 2.004 format) and shows a preview of the label. This processing happens on the device.

In this prototype:

  • the camera scanner is not connected: the scan button explains that it is unavailable;
  • transfer texts can only be entered through demonstration tools that exist in development (debug) builds;
  • writing an NFC tag is simulated in memory: no tag is programmed or read.

Permissions: the inspected iOS and Android project files declare no camera or NFC permission, and the app does not ask for one. The Android development and profiling configurations include the Internet permission used by Flutter’s development tools; the main Android configuration does not.

The content of a QR is chosen by the person who created it. It usually describes a filament (brand, material, colour, temperatures, references), but it can contain any text, including links or information its author considers confidential. Treat a transfer QR like any document you share.

What the app does not do

In the code and dependencies inspected, Companion has no user account and no server of its own, does not upload transfers, and includes no analytics, advertising or crash-reporting service.

Links and file paths that appear in a transfer are shown as plain text: the app never opens or downloads them. The manufacturer logos the app can show are bundled with it; none is loaded from the network.

Limits of this statement: it is based on an inspection of the source code and declared dependencies, not on a network capture of a distributed build. Some packages in the project’s dependency tree can provide network or logging functions; the inspected app code does not use them. The operating system, the app store and development tools may process their own diagnostics or traffic, which this policy does not control.

Storage and retention

The transfer, its preview, any error and the result of a simulated write are kept in memory for the current session only. The app lets go of them when you load another QR, return to the home screen or start over: use one of these to clear the current transfer. Cancelling a write keeps the preview of the same QR on screen.

Letting go means the app keeps no reference to the data; it is not a guaranteed secure erasure of the device’s memory. When the operating system actually ends the app’s process, the session ends with it. Leaving the app or moving it to the background does not clear the session by itself.

The language chosen in the app is kept in memory and is not saved.

The inspected code does not implement a scan history, an export or a backup of transfers. Files that the operating system or runtime may create on their own (caches, system backups) have not been measured for this prototype.

Integrity is not authentication

The SHA-256 digest in an SSQR1 transfer lets Companion detect that the content was damaged or changed. It does not prove who created the QR and does not encrypt anything: anyone who can see a QR can read what it contains.

A transfer that is damaged, altered or in an unsupported format is refused, and no label data from it is shown.

Contacting the project

Contacting the project is voluntary and separate from using the app. Choose the address that fits your request:

  • questions about this policy, privacy requests and anything that should stay private: ArN-LaB Privacy, privacy@arnlab.simplelogin.com;
  • technical help with SpoolScribe Desktop or Companion: SpoolScribe Support, spoolscribe@arnlab.simplelogin.com (see Support);
  • other questions about the project: ArN-LaB Support, support@arnlab.simplelogin.com.

When you write by e-mail, the project receives your e-mail address and the content and attachments you choose to send. These messages are used to answer and follow up on support or privacy requests, with no marketing. These addresses are aliases: messages pass through the SimpleLogin forwarding service and the e-mail providers involved. These exchanges are separate from the processing done by the app on your device and from the technical data of this website. Retention is limited to handling the request and any necessary follow-up. Any longer retention must have a justified purpose, such as establishing or defending a legal claim. We do not promise an automatic purge or a uniform deletion deadline. To ask about retention or request erasure, contact privacy@arnlab.simplelogin.com. No guaranteed response time, encryption or anonymity is promised for e-mail.

For a public technical problem that contains nothing sensitive, you may also open an issue on GitHub Issues (optional). Issues and their comments are public: anyone can read them, and GitHub processes them under its own privacy statement. A GitHub account is needed to open an issue. Never post a confidential QR, a personal catalogue, credentials or other private information in an issue. No specific retention period is promised for issues: they remain visible according to GitHub’s features and the repository’s moderation.

Security vulnerabilities can be reported privately through GitHub vulnerability reporting. That channel is for security issues, not for general privacy requests.

This website

These pages are static files hosted on GitHub Pages. They contain no tracker, analytics, advertising, form or cookie of our own, and load no font or script from another site. These pages are published in English. Legacy language fragments are redirected locally to their English section; nothing is stored in your browser.

GitHub, like any web host, may process technical connection data, including your IP address, to deliver and secure it. See the GitHub General Privacy Statement. This policy does not describe the GitHub platform as a whole.

Your choices and requests

The app has no account and sends no transfer to a server run by the project: the app itself leaves no account to delete and no stored transfer to retrieve. This does not cover information you choose to send to the project yourself, for example by e-mail or in an issue. To clear what the app holds, return to the home screen or start over; you can also uninstall it.

Depending on where you live, you may have rights over your personal data. For questions about this policy, or about personal data you have shared with the project (for example by e-mail or in an issue), write to ArN-LaB Privacy, privacy@arnlab.simplelogin.com. Requests about a GitHub account or about content on GitHub follow GitHub’s own channels and the features of the platform.
